# API Testing Guide - Delícias da Lu

This guide explains how to use the provided testing tools to interact with the API and test the error tracking system.

## 📋 Available Testing Files

### 1. **Postman Collection** (`Postman-Collection.json`)

Import this collection directly into Postman to access all API endpoints organized by category.

**How to import:**
1. Open Postman
2. Click "Import" button (top left)
3. Select the `Postman-Collection.json` file
4. The collection will be imported with all requests organized by resource

**Collection includes:**
- Health & System checks
- All 10 Error Types
- Error Instance retrieval
- Authentication (login, refresh token)
- Menu CRUD operations
- Cake Builder components
- Orders management
- Contacts management
- Site configuration

**Variables in collection:**
- `baseUrl` - Set to `http://localhost:8080/v1` (adjust if your server runs on different port)

---

### 2. **Interactive Browser Dashboard** (`error-testing-dashboard.html`)

Open this HTML file directly in your browser for an interactive testing experience.

**How to use:**
1. Open `error-testing-dashboard.html` in your browser (or right-click → Open with → Browser)
2. Set your API Base URL (defaults to `http://localhost:8080/v1`)
3. Optionally paste your JWT token for protected endpoints
4. Click on error types, trace IDs, or generate test errors

**Dashboard features:**
- 📋 **Error Types** - Click any error type to fetch its documentation
- 🔍 **Error Instances** - Enter a trace ID to retrieve error instance documentation
- 🌐 **Quick API Requests** - Test health, menu, orders, config endpoints
- ⚡ **Error Generators** - Trigger test errors to populate error instances
- 📍 **Trace ID Display** - Automatically extracted and displayed from responses
- 📋 **Copy Functions** - Copy response or cURL command to clipboard
- 💾 **Auto-save** - Remembers your API base URL between sessions

---

### 3. **REST Client Format** (`requests.http`)

If you use VS Code with the REST Client extension, use this file directly.

**How to use:**
1. Install [REST Client extension](https://marketplace.visualstudio.com/items?itemName=humao.rest-client)
2. Open `requests.http` in VS Code
3. Click "Send Request" button above any request
4. Response appears in a new tab

## 🚀 Quick Start Workflow

### Step 1: Start the API Server
```bash
go run cmd/main.go
```

The server will:
- Initialize Firebase Firestore connection
- Seed 10 default error types
- Start listening on `http://localhost:8080`

### Step 2: Test Error Types
Use any testing method above to request:
```
GET /v1/error?filter=type&identifier=not-found
GET /v1/error?filter=type&identifier=invalid-credentials
... (10 total error types available)
```

Response will be HTML documentation page for that error type.

### Step 3: Generate a Test Error
Request a non-existent resource:
```
GET /v1/menu/items/invalid-item-id
```

This will:
- Generate a trace ID (e.g., `a1b2c3d4e5f6g7h8`)
- Record the error to Firestore `instances` collection
- Return the error with `X-Trace-Id` header

### Step 4: Query Error Instance
Copy the trace ID from the response and request:
```
GET /v1/error?filter=instance&identifier=a1b2c3d4e5f6g7h8
```

Response will be HTML documentation page for that specific error instance with:
- Error details
- Request URL and method
- User agent
- Trace ID
- Request timestamp
- Status code

## 📊 Available Error Types

All 10 predefined error types are accessible:

| Identifier | Status | Description |
|-----------|--------|-------------|
| `not-found` | 404 | Resource not found |
| `invalid-type` | 400 | Invalid type provided |
| `invalid-credentials` | 401 | Wrong username/password |
| `invalid-token` | 401 | Invalid or expired token |
| `unauthorized` | 401 | Not authorized to access |
| `type-not-found` | 404 | Error type not found |
| `instance-not-found` | 404 | Error instance not found |
| `invalidDocumentLenght` | 400 | CPF/CNPJ invalid length |
| `invalidFilter` | 400 | Invalid filter parameter |
| `unexpectedUnhandledError` | 500 | Unexpected server error |

## 🔐 Authentication

For protected endpoints (POST, PUT, DELETE), you need a JWT token:

1. **Get Token:**
   ```
   POST /v1/auth/login
   Content-Type: application/json

   {
     "username": "juliosshoji",
     "password": "password123"
   }
   ```

2. **Use Token:**
   Add header to requests:
   ```
   Authorization: Bearer YOUR_TOKEN_HERE
   ```

---

## 📍 Trace ID Propagation

Every request generates or propagates a unique trace ID:

1. **Generated by server** - If not provided
   ```
   GET /v1/error?filter=type&identifier=not-found
   X-Trace-Id: a1b2c3d4e5f6g7h8  # Auto-generated
   ```

2. **Custom trace ID** - Send your own
   ```
   GET /v1/menu/items
   X-Trace-Id: my-custom-trace-123
   ```

The trace ID is:
- Included in all logs (see Firestore instances collection)
- Returned in response headers
- Used to query error instances via `/v1/error?filter=instance&identifier={traceId}`

## 💾 Firestore Collections

The system maintains two error collections in Firestore:

### 1. `types` Collection
Stores predefined error type definitions:
```
/types/not-found
  ├─ html: "<html>...</html>"  # Rendered documentation
  └─ updated_at: timestamp

/types/invalid-credentials
  ├─ html: "<html>...</html>"
  └─ updated_at: timestamp
... (10 total)
```

### 2. `instances` Collection
Stores error occurrences:
```
/instances/{trace-id}
  ├─ title: "Error Title"
  ├─ type: "error-type-identifier"
  ├─ trace_id: "a1b2c3d4e5f6g7h8"
  ├─ request_url: "/v1/menu/items/invalid"
  ├─ request_method: "GET"
  ├─ status: 404
  ├─ user_agent: "Mozilla/5.0..."
  ├─ request_date: timestamp
  ├─ html: "<html>...</html>"  # Rendered documentation
  └─ request_body: "{...}"
```

## 🧪 Test Scenarios

### Scenario 1: Not Found Error
1. Make request: `GET /v1/menu/items/nonexistent`
2. Note the `X-Trace-Id` from response
3. Request: `GET /v1/error?filter=instance&identifier={traceId}`
4. See error instance documentation

### Scenario 2: Authentication Error
1. Make request: `POST /v1/auth/login` with wrong password
2. Get `invalid-credentials` error with trace ID
3. Query error instance to see login attempt details

### Scenario 3: Authorization Error
1. Make request: `POST /v1/menu/items` without token
2. Get `unauthorized` error with trace ID
3. Query error instance to see access attempt details

## 🐛 Debugging

**View logs:**
- Application logs appear in terminal where you ran `go run cmd/main.go`
- Each log entry includes: `trace_id`, `user_id`, `caller_file`, `caller_line`

**Browser console:**
- Open browser DevTools (F12)
- Check Network tab to see request/response headers
- Trace ID visible in response headers

**Firestore:**
- Open [Google Cloud Console](https://console.cloud.google.com)
- Navigate to Firestore → Collections
- View `types` and `instances` collections
- Check documents for trace IDs and error details

## 🆘 Troubleshooting

**Firebase Connection Error:**
```
credentials: could not find default credentials
```
Solution: Run `gcloud auth application-default login`

**Port Already in Use:**
```
address already in use
```
Solution: Kill existing process or change port in `cmd/main.go`

**CORS Issues:**
Open dashboard from `file://` protocol may have CORS restrictions.
Solution: Start a local server:
```bash
# Python 3
python -m http.server 8000

# Node.js
npx http-server
```
Then access: `http://localhost:8000/error-testing-dashboard.html`
